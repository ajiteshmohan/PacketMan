1 About the Project

Educational institutions rely on campus Wi-Fi infrastructure to connect high-density user populations across lecture halls, computer labs, and libraries. In these environments, radio-frequency (RF) interference, channel contention, distance attenuation, multipath fading, and access-point handoffs generate significant wireless packet loss.

Standard Transmission Control Protocol (TCP)—the fundamental transport protocol powering web browsing, video streaming, academic portals, and file transfers—was fundamentally designed under the assumption of wired networks: any dropped packet is treated as an indicator of router queue congestion. Consequently, TCP reacts to random wireless packet corruption by aggressively slashing its congestion window (cwnd), triggering retransmission timeouts (RTO), and throttling transmission speed—inflicting catastrophic, unwarranted throughput collapse even when network buffers are completely empty.

PKT MAN addresses this fundamental challenge by engineering a complete, two-PC client/server framework that:

  • Establishes authentic, high-throughput TCP sessions over live Wi-Fi networks.
  • Injects controlled, dynamically changing wireless packet loss schedules in real time using the Linux kernel traffic-control engine (tc netem).
  • Extracts granular, sub-second TCP telemetry directly from the operating system kernel via struct tcp_info socket options.
  • Employs a dual-layer diagnostic engine (deterministic RFC heuristics + Random Forest machine learning) to distinguish wireless loss from bufferbloat congestion.
  • Provides a unified, modern Frosted-Glass Engineering Dashboard for live control, telemetry playback, and publication-ready visualization.

Project Objectives

  • Live Wi-Fi Testbed: Measure real RF and transport-layer conditions across educational campus Wi-Fi links.
  • Dynamic Loss Schedules: Apply multi-phase dynamic loss patterns (e.g., 1% → 5% → 10% → 5% → 1% and Review 2's 1% → 5% → 10% → 2%) to observe degradation and recovery trajectories.
  • Dual RTT Telemetry: Cross-correlate kernel smoothed RTT (krtt) with application-layer ping round-trip times (app_rtt) to isolate true physical network latency from head-of-line (HoL) socket blocking.
  • Automated Diagnostics: Classify every 0.5-second measurement window into root causes (Normal, Random Wireless Loss, Congestion Collapse, Link Interruption) and output actionable network remediation guidance.
  • Relational Persistence & Web Interface: Store all session telemetry in an embedded SQLite database (experiments.db) and visualize live streams using React and Recharts.

2 Working Principle & Loss Dynamics

2.1 How TCP Reacts to Packet Loss

TCP maintains a sending throttle known as the Congestion Window (cwnd), representing the maximum number of unacknowledged data segments permitted in flight. Because standard TCP implementations (Tahoe, Reno, NewReno, and CUBIC) interpret segment loss as a signal of router queue exhaustion, the protocol responds aggressively through four primary mechanisms:

Mechanism Trigger Condition TCP Window Adjustment Kernel Diagnostic Signature
Slow Start Connection establishment or recovery following an RTO timeout. cwnd doubles every RTT (2× growth) until reaching the slow-start threshold (ssthresh). cwnd < ssthresh, Congestion Avoidance State: Open (0).
Congestion Avoidance Normal steady-state transmission when cwnd ≥ ssthresh. Additive increase: cwnd grows linearly by approximately 1 segment per RTT. cwnd ≥ ssthresh, ca_state = Open (0), zero retransmission delta.
Fast Retransmit / Fast Recovery Arrival of 3 duplicate ACKs or SACK loss indications. Retransmits missing segment immediately; sets ssthresh = cwnd / 2, adjusts cwnd = ssthresh. ca_state = Recovery (3); instantaneous retransmission delta rises.
Retransmission Timeout (RTO) No ACK received before the RTO timer expires (≥ 200 ms). Severe penalty: cwnd = 1 MSS, ssthresh = cwnd / 2, RTO timer doubles exponentially. ca_state = Loss (4); rto_backoff ≥ 1; complete throughput stall.

2.2 Why Wi-Fi Loss Hurts So Much: The Mathis Model

The theoretical upper bound on TCP throughput under steady-state packet loss is governed by the classic Mathis Formula (Mathis et al., ACM SIGCOMM CCR 1997):

Throughput ≤ (MSS / RTT) × 1.22 / √p

Where MSS is the Maximum Segment Size (1,448 bytes over standard Ethernet MTU 1,500), RTT is the path round-trip time, and p is the fractional packet-loss probability. This equation highlights three profound structural realities of wireless TCP performance:

  1. Inverse Square-Root Penalty: Throughput collapses inversely with √p. Even a slight 1% wireless packet loss (p=0.01) penalizes throughput by more than 50%. At 10% loss (p=0.10), theoretical throughput collapses by over 85%.
  2. The RTO Cliff: The Mathis formula assumes loss is repaired solely via Fast Retransmit. When loss exceeds 5%, successive packet drops within the same window prevent duplicate ACKs, forcing TCP into expensive RTO timeouts. During an RTO, the sending window drops to 1 segment, and exponential timer backoff keeps the connection idle for hundreds of milliseconds after the channel clears.
  3. 802.11 MAC-Layer Compounding: At the physical layer, Wi-Fi radios already perform up to 7 link-layer frame retries. When interference causes frame drops, MAC retries inflate transmission jitter, which inflates TCP's measured RTT—further depressing the Mathis throughput bound.

3 What Errors are Detected?

PKT MAN implements an explicit separation between directly measured TCP symptoms (observable facts verified from operating-system kernel data structures) and inferred root causes (derived via multi-feature statistical and machine-learning analysis).

3.1 Symptoms: Measured Directly from the Kernel

Observed Symptom Deterministic Detection Rule (0.5 s Window) Transport Layer Meaning
fast_retransmit retrans_delta > 0 OR ca_state == 3 (Recovery) Loss repaired via duplicate ACKs / SACK without timer expiration.
timeout_rto ca_state == 4 (Loss) OR rto_backoff ≥ 1 RTO timer expired; flow throttled to 1 MSS with exponential backoff.
cwnd_collapse cwnd ≤ 0.50 × cwnd_prev Sender experienced severe window reduction (≥ 50% drop).
rtt_inflation rtt ≥ 1.80 × rtt_min AND (rtt - rtt_min) ≥ 10 ms Queue buffer buildup along the path (bufferbloat congestion signature).
stall throughput ≤ 0.02 × throughput_p95 Zero or near-zero throughput delivered during measurement window.

3.2 Inferred Root Causes: Dual-Layer Loss Differentiation

Because standard TCP headers do not indicate why a packet was lost, PKT MAN uses a multi-dimensional correlation of RTT inflation, loss ratio, and RSSI signal strength:

Detected Class Multi-Feature Signature Granular Detail Physical Real-World Cause
Wireless Loss Retransmissions / RTO occurring with flat RTT (rtt_ratio < 1.35). Weak Signal if RSSI < -75 dBm;
Interference if RSSI ≥ -70 dBm.		 Co-channel RF interference, microwave/Bluetooth noise, multipath nulls.
Congestion Retransmissions preceded by inflated RTT (rtt_ratio > 1.80). Queue Buildup (delay rise);
Buffer Overflow (delay + loss).		 Router bottleneck bufferbloat, competing bandwidth flows, saturated AP.
Link Interruption Zero bytes ACKed (≥ 0.5 s), high RTO backoff, throughput collapse. AP Disassociation / Deep Fade. Client roaming between APs, physical obstacle obscuring antenna, temporary disconnect.

4 System Design & Architecture

4.1 Physical Testbed Architecture

The PKT MAN testbed connects two physical computers across an educational 802.11ac/ax wireless network:

  • PC-1 (Server / Receiver): Runs server.py, binding to TCP port 5201. Accepts incoming client connections, decodes application frames, computes independent application-level goodput every 0.5 s, immediately echoes timestamped ping frames to facilitate RTT calculation, and logs records to CSV.
  • PC-2 (Client / Sender): Runs client.py. Contains three concurrent threads:
    1. Bulk Sender Thread: Transmits continuous length-prefixed data frames at a configurable rate cap (e.g. 10–20 Mbps).
    2. Pinger Thread: Emits high-frequency timestamped ping probes every 200 ms to compute true application-level round-trip times.
    3. Receiver Thread: Collects server goodput reports and echoes.
    4. Kernel Polling Loop: Polls the OS kernel every 0.5 s via getsockopt(SOL_TCP, TCP_INFO), advances the dynamic loss schedule via tc netem, and writes telemetry to CSV and SQLite.

6 Detection & Classification Method

Every 0.5-second measurement window is processed through a sequential dual-layer diagnostic pipeline:

6.1 Layer 1: Deterministic RFC Heuristics

Layer 1 evaluates immediate physical invariants:

  • Stall: Flagged if throughput ≤ 2% of the session's 95th percentile. Attributed to Link Interruption if accompanied by RTO backoff or retransmissions.
  • RTT Inflation: Flagged if R/R_min ≥ 1.80 with at least 10 ms absolute queueing delay. Attributed to Congestion.
  • Wireless Loss: Flagged if retransmissions occur while RTT remains flat (R/R_min < 1.35).

6.2 Layer 2: Random Forest Machine Learning Classifier

To capture complex non-linear interactions across multiple features, PKT MAN trains an ensemble Random Forest classifier:

  • Input Feature Vector (7 Features):
    1. loss_est_pct: Measured packet loss percentage (Δretrans / Δsent × 100).
    2. rtt_ratio: Instantaneous RTT normalized by baseline path RTT (R / R_min).
    3. cwnd: Instantaneous congestion window in segments.
    4. retrans_delta: Count of retransmitted segments within the 0.5 s window.
    5. d_tp_ratio: Window-to-window throughput change ratio.
    6. ca_state: Kernel Congestion Avoidance state (Open=0, Recovery=3, Loss=4).
    7. rto_backoff: Exponential backoff exponent for retransmission timers.
  • Hyperparameters: 200 decision trees, maximum depth of 15, balanced class weighting to handle minority classes (link interruption).
  • Grouped 5-Fold Cross Validation: Windows from the same physical run are strictly kept within the same fold to prevent data leakage between adjacent time windows.

7.3 Dynamic Schedule Degradation & Recovery

Figure 5 illustrates the five-panel telemetry timeline captured during the multi-phase dynamic loss cycle (1% → 5% → 10% → 5% → 1%):

Key Physical Observations:

  • Symmetric Degradation and Recovery: During the initial 1% loss phase (0 ≤ t < 12 s), throughput averages 8.4 Mbps. As loss steps up to 5% (12 ≤ t < 24 s), throughput drops to 5.1 Mbps. At 10% loss (24 ≤ t < 36 s), throughput collapses to 2.6 Mbps. Crucially, as loss steps back down through 5% and 1%, TCP recovers to 8.6 Mbps—confirming that window degradation is fully reversible once wireless noise subsides.
  • RTT Divergence Discriminator: Throughout the entire wireless loss experiment, kernel smoothed RTT (krtt) remains remarkably constant at ≈ 11 ms. In stark contrast, application-layer ping RTT (app_rtt) exhibits severe intermittent spikes exceeding 150 ms (and up to 900 ms under 10% loss). This empirical divergence proves that the network path delay is unchanged; the apparent delay experienced by applications is entirely caused by Head-of-Line (HoL) blocking in the socket buffer while awaiting retransmissions of missing packets.

7.4 Empirical Validation against the Mathis Formula

As demonstrated in Figure 6 (Left), empirical throughput closely follows the Mathis model at low loss (p ≤ 0.03). At higher loss (p ≥ 0.05), empirical measurements fall significantly below the theoretical curve. This occurs because the Mathis model assumes all drops are recovered via Fast Retransmit. On real Wi-Fi links, burst losses trigger expensive RTO timeouts, which force cwnd = 1 and halt transmission entirely during exponential backoff.

9 Limitations & Threats to Validity

  • Wi-Fi Driver Invariants: Standard operating systems abstract the 802.11 MAC layer behind the network socket interface. Link-layer frame retries occur entirely in network card firmware and are not directly exposed in struct tcp_info, appearing to TCP as subtle RTT jitter.
  • Operating System Differences: Complete kernel struct tcp_info extraction requires a Linux or WSL2 kernel. On native Windows hosts, the framework gracefully falls back to high-frequency application ping RTT measurements.
  • Congestion Control Variants: The experiments reported herein utilized standard TCP Reno/CUBIC. Advanced delay-based or hybrid algorithms such as TCP BBR (Bottleneck Bandwidth and RTT) respond to random wireless loss with substantially greater resilience because BBR does not interpret loss as congestion.
  • Access Point Contention: In uncontrolled campus environments, background student traffic introduces variable cross-traffic delays that cannot be strictly scheduled by the local testbed.

10 Conclusion & Future Scope

PKT MAN successfully delivers a robust, reproducible, and academically rigorous network simulation and measurement framework for analyzing TCP performance under dynamic wireless packet loss. By bridging raw kernel socket telemetry (TCP_INFO), controlled traffic shaping (tc netem), and a dual-layer machine learning classifier (98.4% accuracy), the framework conclusively demonstrates why standard TCP suffers severe throughput degradation over Wi-Fi and provides the tools necessary to diagnose and mitigate wireless transport inefficiencies.

Future Scope:

  • TCP BBR vs. CUBIC Comparative Benchmarking: Extending the client testbed to switch congestion control algorithms dynamically via setsockopt(TCP_CONGESTION) to demonstrate BBR's superior wireless throughput.
  • Multi-AP Mobile Roaming Testbed: Deploying physical robotic carts or handheld measurement nodes across campus to analyze 802.11r handoff stalls in real time.
  • Kernel eBPF Telemetry Probing: Implementing eBPF (Extended Berkeley Packet Filter) kprobes to capture instantaneous MAC-layer retransmission counts directly from the wireless driver.
